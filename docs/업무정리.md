## 1. 직무 한 줄 요약

**HBM(고대역폭 메모리) 패키징 공정에서 마이크로범프를 전해도금(ECD/EP)으로 만드는 공정을 맡고 있습니다.**
도금 조건과 장비를 관리하고, 범프 관련 불량의 원인을 물리 모델과 문헌으로 규명해 대책을 세웁니다.
이 과정에서 만든 지식을 시뮬레이터와 교육자료로 정리해 신입·팀 엔지니어에게 전달합니다.

| 항목 | 내용 |
|---|---|
| 제품 | HBM 계열 (base die / core die 적층 구조) |
| 공정 | 웨이퍼 레벨 범프 전해도금 — Cu / Ni / SnAg 다층 범프 |
| 관리 대상 | 도금액 농도·첨가제, 전류밀도·도금 시간, 장비 핵심 파츠(립씰·애노드·멤브레인·순환계 등) |
| 연계 공정 | 포토(레지스트 패턴), 리플로우, 적층(STACK), 몰드, 실장(SMT)·신뢰성 |

## 2. 업무 영역

### 2-1. 불량 원인 분석과 대책 수립

현상 → 가설 → 정량 모델 → 문헌 근거 → 검증 DOE → 보고 순서로 진행합니다.

| 주제 | 하는 일 |
|---|---|
| 범프 찢어짐(crack) | 범프 배치 → 형상 → 잔류응력 순서로 원인을 정량화하는 물리 모델과 시뮬레이터를 만들었습니다. 계측 데이터를 넣으면 wafer×site 단위로 파단 비율을 일괄 계산합니다. |
| Non-melting(비용융) | 도금 장비의 유동 방식 차이가 확산층과 합금 조성에 주는 영향을 분석하고, 전류밀도 조건 변경 테스트를 설계했습니다. |
| 범프 높이 산포 / warpage | 높이 산포(coplanarity)와 휨이 적층 공정에서 범프에 주는 영향을 정량 분석하고, 대책안(패턴 치수 조정 vs 솔더량 조정)을 비교했습니다. |
| 적층 계면 분리 | 특정 계면에 분리가 몰리는 현상에 대해 원인 후보를 정리하고, 판별 계획을 세웠습니다. |
| IMC 브리징·void | 금속간화합물 상전이에 따른 체적수축이 void를 만든다는 가설을 세우고, 기구를 해석해 검증 DOE를 만들었습니다. |
| 실장 후 박리 | 몰드 박리와 범프 찢김에 대해 문헌을 조사하고 우리 조건에 대입했습니다. |

### 2-2. 공정 변경 근거 작성

- 합금 조성 타겟 변경에 대한 내부 qualification 근거와 심의 자료를 만듭니다.
- 심의에서 받는 질문, 예를 들어 "제품 신뢰성에 문제가 없는가", "장비가 달라도 결과가 같은가"에 질문별로 답하도록 자료를 나눕니다.

### 2-3. 문헌·특허 조사

- 주제별로 논문 수십 편과 특허를 모아 **기구(mechanism) 축**으로 분류합니다.
- 논문마다 한국어 요약, 신뢰도, 핵심 그림, 우리 조건과의 차이(예: 무전해 vs 전해 Ni)를 붙입니다.
- 원문을 못 받은 문헌은 받는 방법까지 정리해 둡니다.

### 2-4. 교육자료 제작 (신입·팀 엔지니어 대상)

| 자료 | 형태 |
|---|---|
| HBM 공정 3D 시뮬레이터 | 공정 스텝을 3D로 따라가는 교육 HTML. 수강생용과 강사용이 따로 있습니다. |
| HBM 단위공정 챔버 원리 | 장비별로 "챔버 안에서 무슨 일이 일어나는가"와 "그 공정으로 무엇을 얻는가"를 설명합니다. |
| ECD 장비 교육자료 | 부품 카드 수십 장에 3D 그림과 2D 도면을 넣었습니다. |
| 도금장비 핵심 파츠 세미나 | 3명이 나눠 발표하는 PPT에 예상 Q&A 100여 문항을 붙였습니다. |
| EP 농도 세미나 | Cu, Ni, SnAg 3부작입니다. |
| EP 시뮬레이션 교육 | 반나절 입문 과정과 3일 과정이 있습니다. |

공통 원칙은 다음과 같습니다.
- **사내망 무설치**: 외부 CDN을 쓰지 않는 단일 HTML 파일로 만들어, 더블클릭만 하면 열립니다.
- **이해 순서**: 쉬운 입문 → 심화 → Q&A 백데이터 순서로 구성합니다.

## 3. 일하는 방식 (패턴)

```
현장 관측 ─▶ 가설 ─▶ 물리 모델/시뮬레이터 ─▶ 문헌 근거 ─▶ 검증 DOE ─▶ 보고(1~2장 요약 + 상세 HTML)
                                    │
                                    └──────────▶ 교육자료로 재활용
```

1. **숫자의 출처 구분**: 모든 수치에 `[측정]`, `[계산]`, `[가정]` 중 하나를 표시합니다.
2. **적대 검증 후 정정**: 배포한 뒤에도 스스로 반론을 세워 보고, 틀린 부분이 있으면 정정본(rev.2)을 냅니다. 이때 "무엇이 틀렸고 왜 틀렸는지"를 앞에 적습니다.
3. **청중별 분량 조절**: 상부 보고는 1~2장, 회의 브리핑은 4장, 실무 해설은 20장 이상으로 만듭니다. 근거는 부속 문서로 따로 둡니다.
4. **도금 인자와 비도금 인자 분리**: 내가 바꿀 수 있는 인자와 다른 공정이 주관하는 인자를 나누어 DOE를 짭니다.
5. **지식의 도구화**: 한 번 분석한 내용을 시뮬레이터와 교육자료로 만들어 다른 사람이 다시 쓸 수 있게 합니다.

## 4. 자주 쓰는 도구·형식

- 단일 HTML 보고서·교육자료 (다크 토글, 외부 의존 없음)
- PPT (상부 보고 1~2장, 세미나용 분할본)
- Python 기반 시뮬레이터 (일괄 계산 스크립트, CSV 입력)
- Markdown 해설서 (Q&A 백데이터, 확인필요 목록)
